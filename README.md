# GitHub from Scratch

A browser-based workshop for people who are new to GitHub. No coding or command-line experience required.

**Duration:** 2 hours, including a 10-minute break.

## What you'll be able to do

By the end, you should be able to independently:

- Create a repository with a README.
- Edit a file and commit the change with a descriptive message.
- Find a commit in history and explain its additions and deletions.
- Correct a mistake with another commit.
- Create and merge a pull request in your own repository.
- Propose a change to someone else's repository through a fork, then review and merge an incoming contribution.

We'll build a handbook for a fictional community cafe. Use invented content throughout: no personal contact details, real workplace documents, passwords, or other sensitive information.

**Private is not a promise of secrecy.** Before uploading, ask: would it be harmful if this became public? If yes, stop and check your organization's rules and get guidance before using GitHub, even in a private or internal repository. Access restrictions reduce exposure; they do not prevent every mistake, account compromise, or copy. Deleting a file does not necessarily remove its history or copies already downloaded.

## Before the workshop

Bring a laptop, charger, and internet access. You only need a browser.
Please [create a GitHub account](https://github.com/signup) and verify your email beforehand if possible. The session includes a five-minute setup demo and attempt; verification delays may need the later catch-up buffer.

Choose a username you're comfortable sharing; you don't need to use your real name.

## Workshop path

| Elapsed time | Activity | Material |
|---|---|---|
| 00:00-00:15 | Welcome, Git vs. GitHub, and safe practice | [Slides](https://navikt.github.io/github-workshop/) |
| 00:15-00:20 | Account setup | [Exercise 01: Setup](exercises/01-setup/) |
| 00:20-00:25 | Create the cafe handbook repository | [Exercise 02, Part 1](exercises/02-first-commit/#part-1-create-your-repository-5-minutes) |
| 00:25-00:35 | Edit/add a file and commit | [Exercise 02, Part 2](exercises/02-first-commit/#part-2-editadd-a-file-and-commit-10-minutes) |
| 00:35-00:45 | Read history and correct a mistake | [Exercise 02, Part 3](exercises/02-first-commit/#part-3-history-and-recovery-10-minutes) |
| 00:45-00:55 | Independent edit and catch-up buffer | [Exercise 02, Part 4](exercises/02-first-commit/#part-4-try-it-yourself-10-minutes) |
| 00:55-01:05 | Break | Step away from the screen |
| 01:05-01:25 | Branch and merge a PR in your own repository | [Exercise 03: Branches](exercises/03-branches/) (8 min), then [04: Pull requests](exercises/04-pull-requests/) (12 min) |
| 01:25-01:30 | Share links in Slack and assign partners | [Exercise 05: Setup](exercises/05-collaboration/#part-1-share-and-pair-5-minutes) |
| 01:30-01:50 | Fork, contribute, review, and merge | [Exercise 05: Contribute](exercises/05-collaboration/#part-2-fork-contribute-review-and-merge-20-minutes) |
| 01:50-02:00 | Check results, parked questions, and reflection | [Completion and next step](exercises/05-collaboration/#completion-and-next-step) |

For the fork exercise, use a public, disposable repository containing fictional content if you're comfortable doing so. Post its link in the Slack channel named by the facilitator; pairs or a contribution ring ensure everyone gives and receives a PR. A restricted Slack channel does not make linked public repositories private.

If you prefer a private practice repository or cannot post in Slack, arrange the alternative in [Exercise 05](exercises/05-collaboration/#access-and-sharing). Do not change visibility or grant access just to keep up.
